The Problem

Engineering workflows are fragmented.

The average mechanical engineer switches between five or more tools before reaching an answer. FORGE AI collapses that into one intelligent workspace.

The Old Way
  • ✗Open five or more separate tools — FEA software, handbook PDFs, a spreadsheet, a search engine, and your email
  • ✗Manual calculation sheets with no context carried between sessions
  • ✗Spend an hour scanning a 400-page standard for a single lookup value
  • ✗No traceability — results can't be linked back to their source
  • ✗Start from scratch every time, with no memory of prior analyses
The Forge Way
  • →One workspace: file viewer on the left, Claude-powered analysis on the right
  • →RAG knowledge base retrieves the exact chunk from your ingested engineering corpus
  • →Drop a PDF or sketch and receive targeted guided questions immediately
  • →Every response includes reasoning and source attribution from retrieved documents
  • →Conversation context maintained throughout — ask follow-ups naturally

Founder

Hikmet Bisen

Founder · Engineer · Builder

FORGE AI started as a personal frustration. As an engineering student, I kept running into the same wall: a question would take thirty minutes to answer — not because the knowledge didn't exist, but because finding it was the actual job.

I wanted a tool that understood the context of my drawing, knew which standard to reference, and could walk me through the calculation without leaving a single tab. That tool didn't exist. So I built it.

FORGE AI is the platform I wish I'd had on every lab assignment, every design project, every late-night session with a textbook that should have just talked back.

Roadmap

Where we're going.

FORGE AI is being built in phases. Here's the full picture — what's shipped and what's coming.

Phase 01 Complete
RAG Foundation
PDF ingestion pipeline — chunk, embed with Voyage AI, store in Supabase pgvector. Cosine similarity semantic search via RPC. Direct httpx REST calls, no Python client dependency.
Phase 02 Complete
FastAPI Backend
/upload, /query, /health endpoints. Claude Sonnet 4.5 integration. slowapi rate limiting, input validation, 10 MB size cap, and security headers.
Phase 03 Complete
React Frontend
Split-screen analysis workspace. File viewer with PDF and image support. Chat interface with guided question chips. Marketing website with four pages.
Phase 04 Upcoming
Guided Onboarding
First-run experience, context-aware question flows, and onboarding document ingest for new workspaces.
Phase 05 Upcoming
Output Layer
Structured report export in PDF and Markdown, calculation templates, and annotated drawing output.
Phase 06 Upcoming
Multi-model Routing
LiteLLM integration for routing across Claude, GPT-4, and open-source models based on query type and user tier.
Phase 07 Upcoming
Polish
Performance optimisation, accessibility pass, mobile experience, and end-to-end test coverage.
Phase 08 Upcoming
Monetisation
Stripe integration, Free / Pro / Enterprise tiers, usage metering, and team workspace management.
